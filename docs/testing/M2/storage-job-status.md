`horvium storage-jobs -state-dir <absolute-storage-ledger>` connects complete native
ledger inspection to the accepted bounded restart projection. See the
[operational runbook](../../operations/M2-job-status.md) for the implemented
flags, authority, output and failure semantics. It reads retained metadata;
no policy/job publication, native storage command, service or management transport
is added. The existing lease opener's first-use private lock creation/sync remains
explicit; the command provisions no directory and never removes the stable lock.

Require actual FreeBSD effective UID 0 and the existing protected root lease,
complete mixed namespace validation and conservative uncertainty/capacity checks.
Read one immutable job view and close the lease before any status output. Keep
original durable events separate from restart presentation; terminal labels release
nothing and every envelope says recovery is unverified. Traverse all pages of 64
from that same view, keep the accepted 1,064-job bound and stage one document under
1 MiB. No full intent, private baseline, session/policy digest or raw native output
escapes. Unknown, unsafe or unavailable stores and cancelled contexts return no
status document. Output failure cannot retract delivered bytes; report failure
with a fixed error, never a fabricated successful query.

## Tests and native qualification

Portable tests prove complete/sorted traversal across 65 records, queued and
terminal presentation, complete empty output, zero/invalid/cancelled refusal,
fixed output errors, argument denial before access, and mixed plain/property
records with private baseline exclusion. The property fixture is synthetic,
generated by the previously accepted `storage.propertyJobFixture` and
`EncodePropertyJob`; it contains no operator inventory or authentication secret.
Its static bytes are embedded only in the test executable, not the product.

The native fixture owns two temporary directories and one copy of its exact test
binary. It re-executes the compiled public `main` command/flag/signal path through
a private test helper, then waits/reaps each child. This is not a new product
switch and does not build/install a standalone product in the guest. It supplies
no disk, pool, mount, daemon or listener. Root-owned synthetic plain and property
records cross the internal page boundary, retaining queued/applying/observing and
terminal states. GUID 100 is independently verified absent from imported pools;
status must still show its retained jobs without native collection.

Require all twenty-one exact assertions: `built_process`, `empty`, `mixed_complete`,
`queued_held`, `applying_held`, `observing_held`, `terminal_retained`,
`private_baseline_hidden`, `repeat_preserved`, `lease_released`,
`active_writer_denied`, `kernel_uid_denied`, `unknown_denied`, `newer_denied`,
`unsafe_file_denied`, `orphan_denied`, `cancelled_denied`, `output_cancelled`,
`native_unavailable_not_consulted`, `lock_preserved` and `fixtures_teardown`.
An owned full output pipe and SIGTERM must produce exit 1 within three seconds;
a supervisor kill cannot satisfy this assertion. Portable tests prove the
45-second lifetime bound and disarming after completion. Actual kernel UID 65534 must refuse the command with no status output. Repeat
queries preserve every record byte and the lock inode; releasing the query lease
permits the independently opened writer. Refused unsafe/unknown/newer/orphan
objects remain unchanged. Record actual ZFS/UFS/softupdates backing separately;
reading softupdates UFS does not qualify metadata publication on that backing.

The checksum-bound `job-status` local suite transfers one cross-built test binary,
uses no guest packages or disk fixture and verifies all command/UID/backing and
host/process teardown evidence. Extend supervisor fallback and both worker cleanup
paths to remove the exact new artifact even after interruption. The regression
suite must reject missing/skipped/failed/duplicate/extra assertions or backing
records; selectors require only the native parent, not a helper test.


Shared runner/supervisor/Makefile changes require one fresh complete portable deep
review even though the new native guest suite is focused. Existing native storage
implementation/tests, codecs, restart semantics and historical manifests remain
unchanged; prior 819-case metadata evidence retains its actual tested source and
is not relabeled. Full built application/helper/client workflows, recovery,
restoration, resources/hardware, browser parity and M2 acceptance remain open.
