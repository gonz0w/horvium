## Contract and Test Design

M2-RUNTIME-002/M2-RECOVERY-001 require publication of a fresh active identity under
both original leases before a new incarnation can be considered. Consume only the
original closed-startup review, with unchanged file receipt, original objects,
complete census, fixed actual native/system observations and repeated current boot.
Reserve generation capacity for the new active record and an eventual closed
successor. Generate a fresh random owner, distinct from the old owner and
installation; retain binding and census exactly. Ordinary successors/reopened
stores remain denied: no old publication acknowledgement is reconstructed.

Publish through the existing actual file/verify/rename/directory-sync discipline,
then independently repeat original native facts and the exact new receipt before
returning the original activation. Capture only the acknowledged publication's
own journal-directory change; later metadata touches cannot become the baseline.
Transfer both original leases once. The old review cannot release the new lifetime.
Entered failure retires both stores, preserves visible old/new history and prevents
retry; no rollback, repair, staged-file deletion or uncertain acknowledgement is
interpreted as success. Close releases leases without a clean journal transition.

This prerequisite is restricted to a confirmed empty ledger. Nonempty histories,
policy/retained-job recovery, configured startup, orderly worker draining and clean
shutdown need their separately qualified consumers. Active history always denies
this path, including changed boot. A fixed root factory reserves the same original
single-use helper registration as commissioning/review before opening any domain.
No admission, metadata mutation consumer, native launch permit, worker, backend,
HTTP/CLI route, configuration or service is enabled.

T1/T2 require exact immutable successor framing and eleven negative candidates;
original review consumption/copy/decoded/context/transfer rules; seven failed or
uncertain transfer/lifecycle variants; original observation/release and review-transfer/release exclusion.
Ordinary active successors retain their accepted framing and cannot resurrect a
closed owner. Old review tests remain required.

T3 publication qualification uses three exact storage parents: actual UFS and ZFS
publication with 122 controls each, and 24 UFS process-cut controls. Twenty-three error
variants surround entropy, original preconditions, every file pipeline stage,
acknowledgement drift and post-publication boot/system/object/context checks.
Four exact-binary children pause after real file sync, real directory sync, full
acknowledgement or actual UID loss with inherited root descriptors. The parent
kills and waits, independently inspects visible history, denies unsafe takeover,
probes both released leases and verifies exact preservation and owned teardown.
Native filesystem identity is actual; storage physical-use/boot transfers remain
synthetic, as in the accepted storage fixtures.

T3 fixed-root qualification uses four exact host parents: retain both original
startup parents and all 186 controls, then add two UFS/ZFS active-publication
parents with 88 controls each. Nine normally waited exact-binary children per
filesystem use separate production registries without resets. Require actual fixed
boot/backing/system composition, fresh identity/retained history, transfer/drift,
actual UID loss, missing/active denial and injected pre/post-publication faults.
Independent parent locks/history/data/backing/domain teardown remain mandatory.
The original eight-minute host parent bound is unchanged; four parents have a
34-minute process bound. The storage process bound is eighteen minutes; its four
cut children have forty-second parent deadlines.

Run both separate suites on both pinned disposable releases, serially. Strict
new evidence must include every new and retained control, distinct real parents,
exact executable hash and complete guest/host/fixture/device/supervisor cleanup.
Failed records remain unqualified. Shared tooling requires fresh full portable
review; final prose can reuse only matching actually executed deep inputs.
Whole-host rollback, actual reboot, hardware power loss, active kernel interruption,
throughput, commercial scale and full M2/release acceptance remain unqualified.

The first implemented fixed-root run exhausted the unchanged eight-minute ZFS
