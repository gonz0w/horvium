## Contract and Test Design

M2-RUNTIME-002/M2-RECOVERY-001 require fresh original startup inspection before a
new incarnation can be published. This component reviews an existing closed
incarnation under both original journal-first leases, using fixed actual native
backing/system and exact raw boot producers. It retains the exact journal file
receipt, original directory/lock/mount snapshots, binding and complete census for
repeated inspection. Closed bytes alone,
ordinary metadata observation, matching hashes or a caller declaration cannot
reconstruct this original review.

Require a valid closed journal with no metadata/native pending or restore barrier,
matching actual binding and complete validated ledger census, bounded generation,
independent UFS/ZFS restore scope and full actual system/owned backing checks.
Repeated current kernel boot reads must agree; the prior clean closed owner's boot
is historical metadata. Active history always denies this review, even with a
changed boot: unclean recovery requires its own explicit qualified decision.
Missing halves, unsafe objects, native errors, drift or incomplete history deny.
Never create or repair a namespace, alter records, clear holds or replay work.

The original read-only review serializes observation/release and rejects copies
or decoded values before touching copied mutexes. An entered inspection error
permanently retires it; pre-entry cancellation consumes no producer. Retain both
leases until original idempotent release. The fixed root factory uses the same
single-use helper registration as fresh commissioning, reserving before opening
any domain. Different paths, failure and release cannot reset that registration.
Finishing an unused fresh activation is unavailable on a startup review.

T1/T2 require four portable parents: candidate consistency and fourteen unsafe
variants, original lifecycle/copy/serialization/context checks, read/cancellation/
release failures, and release exclusion while observation is active. Ordinary
journal successors must continue to deny owner replacement. No new mutable
journal format, publication receipt or private persistent protocol is introduced.

T3 uses a dedicated `execution-startup` suite, retaining the existing runner's
snapshot/device ownership and supervised cleanup. Two independently owned UFS/ZFS
parents use actual initial activation/unused close to seed closed history and a
separate unclean active history. Nine exact-binary children per parent use fresh
production process registries, never fixture resets: clean, same-inode touch,
active, missing, ledger drift, actual UID drop with inherited root descriptors,
and boot/system/late-directory fault transfers around actual native producers.
Parent checks wait
results, both released locks, exact retained history, disjoint declared metadata
backing, original data sentinel and complete filesystem/device/mount teardown.
Require all 93 named controls per profile and reject incomplete/old host evidence.
Existing native suites, selectors and historical manifests remain separate.

This qualifies read-only closed startup review only. Durable new-incarnation
publication, unclean changed-boot/root recovery, journaled mutation consumption,
global native launch, worker/supervisor/backend assembly and operator configuration
remain required. Retained nonempty job/history startup, actual reboot recovery,
active kernel interruption, whole-host rollback, power loss, throughput and
commercial scale are not qualified by empty warm closed fixtures. Runtime writes
remain denied; no host service or GitHub Actions execution is enabled.

## Executed qualification

Four portable behavioral parents first failed against denial stubs, and the new
evidence consumer rejected its positive fixture against its own denial stub.
The signed native stub failed the two positive original-review parents on actual
UFS/ZFS. A second signed native checkpoint reproduced an accepted same-inode
ledger-directory touch between observations on both filesystems. The fix retains
full original directory, lock and mount snapshots across the review lifetime,
before and after each native/boot/system observation. Both expected failed native
runs are unqualified; their owned fixtures, guests and supervisors were cleaned.

Signed implementation `c824a96eb58e5244fc2d61548900ab62aa89f935`, based on
`44e70d4730eef66fe356caf8ec6db18d80152109`, passed on pinned disposable
FreeBSD/amd64 15.1 and 14.5. Each target passed two native UFS/ZFS parents and 186
controls, including all 93 per filesystem. All eighteen exact-binary children per
guest were waited normally; parents independently checked retained history,
released locks, declared disjoint backing, data preservation and domain/data
teardown. Both targets used one compiled artifact. Parent deadlines are eight
minutes, with an eighteen-minute bound for the two-parent process. Injected
boot/system/late-directory faults wrap actual native producers; they are not real
reboot or kernel interruption evidence. The warm fixtures have empty history;
retained nonempty job histories and configured startup recovery are not qualified.

Four portable parents, fourteen candidate denials, three original-review failure
variants and four evidence-consumer tests passed. Local review passed
check/lint/test/secrets, all 180 tooling tests, eleven race packages and all 54
bounded fuzz targets. Final prose review reruns the baseline and may reuse that
executed deep record only for exact unchanged inputs/base/environment.

All 440 original Go inputs and 103 historical manifests, including 98 M2
manifests, retain exact bytes. Existing storage publishers/formats, host producers,
native fixtures and state/system scripts/checkers are unchanged. The shared
runner adds only the separate suite, its fixture selection and strict validation;
old suite values, validation branches and other helpers were checked for
preservation. Prior state/host evidence remains historical and bound to its
actual executed source; this isolated new gate does not claim a redundant rerun.

The [sanitized execution manifest](execution-startup-review-manifest.json) records
source, binary/image/tool, failing-first, review and teardown hashes. Both positive
native runs verified independent domain/data teardown and preserved or removed
all declared guest devices and host artifacts. Compiled owned test artifacts were
removed. All owned VMs and supervisors are stopped; no host service or GitHub
Actions execution was enabled. Concurrent dashboard work in the primary checkout
retains its original bytes.

The subsequent [original active-publication consumer](closed-startup-activation.md)
consumes this review once for a confirmed empty ledger and retains both original
leases in a new acknowledged active lifetime. Both original startup parents/all
186 controls are rerun with that consumer on both targets. The historical manifest
above remains unchanged and bound to its originally executed source. Nonempty
history, recovery, clean retirement and runtime launch remain separate gates.
